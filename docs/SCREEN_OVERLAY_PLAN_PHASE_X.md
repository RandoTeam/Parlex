# План Фазы X: Реконструкция Экранного Перевода и Эффект Заморозки (Google / Apple Glass)

**Статус**: Активный (проектирование и подготовка к реализации)  
**Дата**: 2026-09-13  
**Версия**: 1.5.1-beta.1 (подготовка к v1.5.2)  
**Компоненты**: `ScreenAccessibilityService`, `ScreenTranslateOverlayService`, `ParlexVoiceInteractionSession`, `ArTranslateOverlayView`, `FastBatchTranslator`, `LiquidGlassShimmerView`

## 1. Контекст и Проблематика

Текущая реализация экранного перевода в `v1.5.1-beta.1` выдает визуальную и текстовую «кашу» по следующим корневым причинам:
1. **Смешение A11y-нод и OCR-кластеризатора**: `ArBoundingBoxClusterer` разработан для сборки отдельных OCR-строк с высотой ~20-30px. Ноды `AccessibilityNodeInfo` из приложений уже являются полноценными многострочными виджетами (высотой до 300-400px). Из-за пропорционального роста порога объединения (`avgHeight * 1.25`) соседние посты, кнопки и временные метки сливаются в единый гигантский прямоугольник с перемешанным текстом.
2. **Захват contentDescription и системных окон**: обход захватывает статус-бар (`TYPE_SYSTEM`), иконки Wi-Fi/батареи и аватары, выводя перевод поверх графических элементов интерфейса.
3. **Отсутствие замороженного кадра (`bitmap == null`)**: в режиме A11y скриншот не делался, из-за чего оригинальный текст приложения просвечивал сквозь полупрозрачные плашки и накладывался на перевод.
4. **Спецсимволы в FastBatchTranslator**: разделители `<<<§>>>` деградируют в Seq2Seq NMT или разбиваются внутренними `\n\n`, вызывая рассинхронизацию индексов.
5. **Баг отрисовки текста в ArTranslateOverlayView**: при анти-коллизии плашек `pillRect` смещается вниз, а неизменяемый `textOffsetY` остается на старом месте.

## 2. Как работает системный экранный перевод в Google (Circle to Search / Assistant)

Архитектура Google Circle to Search и Google Assistant базируется на трех столпах:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Триггер (Жест / Кнопка)                         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
       ┌────────────────────────────┴────────────────────────────┐
       ▼                                                         ▼
[Аппаратный захват кадра]                     [Нативное извлечение данных]
• Заморозка экрана за 1 кадр                  • AssistStructure (Assist API)
• Захват HardwareBuffer                       • AccessibilityNodeInfo (A11y API)
• Блокировка движения подложки                • Точные Bounds, Leaf Nodes, Classes
       │                                                         │
       ▼                                                         ▼
[Визуальный переход Google/Apple Glass]       [Интеллектуальная фильтрация]
• Периметральное свечение по кантику экрана   • Отсечение TYPE_SYSTEM (статус-бар)
• Мягкая виньетка и блюр границ кадра         • Игнор текста, совпадающего с target
• Эффект стеклянного мерцания (Shimmer)       • Защита от захвата описаний иконок
       │                                                         │
       └────────────────────────────┬────────────────────────────┘
                                    │
                                    ▼
                 [In-Place AR Рендеринг Перевода]
                 • Замена текста строго на своих координатах
                 • Высококонтрастные Liquid Glass подложки
                 • Нулевая коллизия с оригиналом (фон заморожен)
```

1. **Мгновенная фиксация экрана (Freeze Frame)**: в момент нажатия экран мгновенно «замораживается» в виде скриншота без запроса разрешений через системный вызов (`takeScreenshot()` в A11y или `onHandleScreenshot()` в Assist). Это устраняет мигание, скролл и движение подлежащего приложения.
2. **Прямое извлечение текста и координат из ОС**:
   - Google использует иерархию представлений (`ViewNode` / `AccessibilityNodeInfo`), получая **точные геометрические координаты в пикселях дисплея** без погрешностей OCR.
   - OCR запускается **только как вторичный fallback** для растровых зон: изображений, видеоплееров, игр и WebView без разметки доступности.
3. **Визуальный стиль Apple Glass / Google Circle**:
   - По периметру экрана (вдоль рамок дисплея) запускается градиентный анимированный контур (свечение и рассеянный блюр).
   - Подложка экрана слегка приглушается.
   - Плашки перевода центрируются строго по оригинальным прямоугольникам виджетов.

## 3. Детальный план реализации (Подфазы X1–X5)

### Подфаза X1: Прецизионный парсер нативных нод экрана (`ScreenTextExtractor`)
* **Файлы**: `ScreenAccessibilityService.kt`, новый компонент `NativeScreenTextExtractor.kt`.
* **Задачи**:
  1. Фильтровать окна: обрабатывать только `AccessibilityWindowInfo.TYPE_APPLICATION`. Игнорировать `TYPE_SYSTEM` (статус-бар, навигацию, клавиатуру, оверлей Parlex).
  2. Брать только **реальный визуальный текст** (`node.text`). Игнорировать `contentDescription` для нетекстовых виджетов (иконки, кнопки без надписей, аватары, чекбоксы).
  3. Обход исключительно листовых нод: если узел содержит дочерние узлы с текстом, не извлекать контейнер целиком.
  4. Топологический порядок чтения (Reading Order): группировка по строкам (Y-band с допуском 14dp) и сортировка слева-направо (X).

### Подфаза X2: Разделение пайплайнов A11y и OCR
* **Файлы**: `ScreenTranslateOverlayService.kt`, `ArBoundingBoxClusterer.kt`.
* **Задачи**:
  1. **Полностью исключить** вызов `ArBoundingBoxClusterer` для A11y-нод. Каждая валидная нода экрана поступает как самостоятельный блок `ArTranslatedBox`.
  2. Сохранить `ArBoundingBoxClusterer` только для fallback OCR со скриншота (когда A11y-нод 0).

### Подфаза X3: Надежный пакетный перевод и языковая фильтрация
* **Файлы**: `FastBatchTranslator.kt`, `ScreenTranslateOverlayService.kt`.
* **Задачи**:
  1. Per-Block Language Filtering: проверять язык каждого блока через `LanguageDetectionEngine`. Если язык блока уже равен `targetCode`, блок не переводится и плашка над ним не создается.
  2. Защищенный пакетный перевод: переход на индексированный транспортный формат без риска схлопывания разделителей, с гарантированным сопоставлением `1:1`.

### Подфаза X4: Визуальный эффект фиксации экрана и Liquid Glass / Google Glow
* **Файлы**: `LensScanEffectView.kt` -> `LiquidGlassShimmerView.kt`, `ArTranslateOverlayView.kt`.
* **Задачи**:
  1. Параллельный вызов `captureSilentScreenshot()` при старте перевода: сохранение `Bitmap` для заморозки подложки.
  2. Создание периметрального эффекта свечения (Border Glow / Perimeter Shimmer):
     - Радиально-линейный шейдер по кантику экрана (цианово-индиговый градиент Google/Apple Glass).
     - Мягкая виньетка и затемнение экрана для акцентирования переведенного слоя.
  3. Исправление бага смещения текста в `ArTranslateOverlayView`: сделать `textOffsetY` мутабельным и синхронно смещать его при выравнивании перекрывающихся плашек.

### Подфаза X5: Верификация и интеграция триггеров
* **Файлы**: `ScreenTranslateOverlayService.kt`, `ParlexVoiceInteractionSession.kt`, unit-тесты.
* **Задачи**:
  1. Проверка работы из всех источников: плавающая кнопка, шорткат громкости, ассистент (`ParlexVoiceInteractionSession`).
  2. Закрытие оверлея по клику в любое свободное место или свайпу от края.
  3. Покрытие unit-тестами логики экстрактора нод и сортировки чтения.
